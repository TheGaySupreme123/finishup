# Yoetz v0.3.0 — independent agent tasks and project coordination

Yoetz **0.3.0** is a public-alpha release that lets several agents work in independent tasks
inside one repository. Parents can delegate work, retain a child's unfinished obligations and
findings, and group related tasks into projects without granting access to arbitrary sibling
content. It also adds a backup-first data upgrade path from 0.2 and carries every repair the
0.2 line published after 0.2.1: the 0.2.2 install fixes, the 0.2.3 integration and session
recovery repairs, the 0.2.4 guided desktop installation, and the 0.2.5 repairs from `main`,
including opt-in required startup for native Claude Code and Cursor plugins. The capabilities
below describe the implementation; native-host and release evidence remain bounded by the limitations below.

Python and npm packages both use **0.3.0**. The public protocol namespace remains **0.1**;
package versions and immutable wire-schema versions advance independently.

## Highlights

- **Independent tasks, explicit delegation.** A parent can hand a child an expiring attach
  handle; child acceptance, cancellation, abandonment, closure and findings remain visible in
  lineage and receipts. A receipt does not close work or erase an unfinished dependency
  (#494–#504, #509, #706, #752).
- **Projects with bounded coordination.** Related tasks can declare overlaps under each source
  workspace's consent. Membership generations fence stale deliveries, grants can be revoked,
  and grouping can be disabled and re-enabled. Overlap detection reads an idle or restarted
  sibling exactly as it reads an active one (#505–#508, #706, #839).
- **Backup-first upgrades.** After unlock, the service upgrades supported older task ledgers
  before admitting writes, retaining verified backups and recorded progress for interrupted
  migrations. Package replacement and fresh host activation remain separate steps (#496).
- **Updates without a full restart.** From 0.3.0 on, `yoetz upgrade --accept` replaces the
  package while hosts, hooks and the service keep running from retained release copies.
  Old exact version pins no longer silently prevent an update; the fresh launcher confirms it.
  Open sessions retain their code and resources. The first Yoetz call of the next session retires
  the previous service and starts the new one, and a process from before the update never replaces its successor. Upgrading from 0.2
  still follows 0.2's stop-first procedure once (#820). Those copies run for normal Ubuntu,
  Debian, Fedora and RHEL accounts, whose default umask `0002` leaves files writable only by the
  account's own private group; a runtime another account can write is refused as
  `release_runtime_group_writable` or `release_runtime_world_writable` with the exact
  `chmod -R go-w` repair.
- **Codex multi-agent v2 identity and recovery.** The bridge understands Codex 0.153.4 child
  rollout headers and token-usage records, preserves native replay identity, and keeps child
  lifecycle transitions distinct from session health. Native installed multi-agent acceptance
  remains open (#499, #507, #754, #752, #762).
- **Responsive reads and durable long reviews.** Immutable projection pages avoid repeated
  ledger replay for small status reads. Busy starts recover their durable route; long reviews
  preserve leases and authenticated responses through client disconnects and recovery rather
  than treating a client timeout as permission for a second dispatch (#745, #748, #750).
- **A retained evaluator runtime.** Codex subscription setup keeps a verified private copy of
  its admitted runtime, so ordinary host updates cannot replace the evaluator. Repair reuses
  the existing sign-in and preserves the final and routine efforts, output limits, timeout,
  retries and fallback role. Runtime identity and all disclosure gates remain enforced (#855,
  #856).
- **Explicit child assignments.** Delegation guidance names the child selector, actor, scope and
  complete publication/check/receipt/closure sequence. Helpers with no selector stay off the
  child ledger; the parent accounts for incorporating their work. The macOS three-host result
  and its partial or untested cells are recorded in the multi-agent runbook (#509, #868).
- **One guided installation for every desktop host.** Codex, Claude Code, Cursor IDE and Cursor
  Agent CLI share the same discover, preview, connect, status, disconnect and reconnect flow on
  macOS, Linux and Windows through WSL 2, with Linux/WSL approval kept on the foreground thread
  and the selected runtime retained in host handoffs. Carried from 0.2.4 (#767, #788).
- **0.2.3 repairs carried forward.** Codex setup registers MCP in the selected Codex home and
  reconfirms a refreshed preview; Cursor registration writes the exact project path and the Agent
  CLI binds to its approved project; newer Codex fractional metadata keeps its record; selected
  observations, protected reads and routine summaries cross local control; contended session
  attachment drains existing users and releases leases through cancellation (#786, #787). The
  0.3 control contracts derive from the released `2.6.1` envelope, so an observation the 0.2.3
  service admits is admitted unchanged after upgrade.
- **Install fixes carried forward.** The documented `uv` command fetches Python 3.14.6, the
  npm launcher installs persistently before delegating, and first-run Codex setup offers its
  default home. The npm release verifier now checks the launcher's two subprocess calls
  (#768, #774, #777).
- **Failures explain recovery and coverage.** Local CLI errors carry recovery directives;
  failed transport writes receive retryable transport classifications; oversized hook input
  reports a scoped coverage gap. Invalid routine summaries no longer stop admission flushes
  (#780, #781, #784, #764).
- **Advice and privacy receipts are more precise.** Paired edits produce one advice finding,
  verification baselines are typed, consumed egress is reconciled after cancellation, and
  privacy receipt commands render timestamps and admit the local purpose on the control wire
  (#782, #761, #783; fixes #731 and #732).
- **Isolation proof names path identity apart from file bytes.** `yoetz service isolation --json`
  now emits the versioned `yoetz.isolation-report/1`, whose `path_identity` block replaces the
  untagged 0.2 `identity` block (`config_digest` was a path digest, not a content digest), and
  `--content-digests` adds a bounded SHA-256/size/existence/time observation of the selected
  config without its content. `yoetz instance status` reports the same `path_identity` block. The
  Codex dogfood parity gate moves to report version 4 and can bind normal-target file bytes
  before and after a run (#567, #571).
- **Connecting a second host keeps the first host's content capture.** Codex setup and a
  repeated `yoetz observe grant` keep Claude Code or Cursor content capture that you already
  enabled. Consent that is already in effect is left untouched, so capture in progress keeps
  its authorization. Content-disable and revoke still end capture, and a later grant does not
  bring it back (#835).
- **A stranded capture handoff cannot hold a workspace at the age limit.** A ticket whose structural
  record can no longer deliver it is retired by that record's delivery, by background service
  maintenance independent of admission, or by a new check's preflight. A genuinely pending
  handoff still counts toward the unchanged pending-age limit. Claude Code and Cursor hooks no
  longer quarantine a queued Codex row in a shared workspace as a content-profile mismatch, and
  `observe status --json` names each retirement (#836). Native re-acceptance of the concurrent
  Codex and Claude Code run is not claimed by source tests.
- **The release-runner test observes its drain.** The parent/worker capture test waits for the
  outbox to empty before the next write, instead of assuming a bounded hook pass drained it
  under runner load (#775).
- **Background advice now actually sends (behaviour change).** With external review configured
  and a privacy policy that allows unattended requests, background AI-powered advice now sends its
  approved, minimized advice packet to your reviewer; the switch was already on by default, but an
  invalid review envelope meant nothing was sent before. The packet follows your review-context
  choice. Under Metadata only, or any policy that requires a preview of each request, background
  advice is skipped and shows `advice_semantic_preview_required`: nothing is queued or sent and no
  approval waits for you. Set `observation.semantic_advice_enabled = false` to stop background
  sends. `yoetz privacy receipts get|list` marks refused receipts whose approvals were never
  sent. Same on Codex, Claude Code and Cursor (#1019).
- **Several projects per agent installation.** One Codex home, Claude Code configuration or
  Cursor configuration now serves projects connected one after another; a second Codex project no
  longer stops with `destination_conflict`. Disconnecting one project keeps what the others use,
  the last disconnect removes the shared pieces, and `setup disconnect --remove-shared` is the
  explicit home-wide removal. The same folder under a second path is refused as
  `project_connected_via_other_path`. When Yoetz cannot verify which projects use the shared
  pieces (an earlier release, or a lost record), it keeps them; for Codex, trusted checkouts that
  merely carry Yoetz's plugin files are listed as possible users and never take over the home's
  marketplace binding, and a disconnect that would leave only those stops as
  `membership_unverified`. A private per-configuration setup lock stops concurrent setups from
  losing a project (#1058).
## What this release does not claim

- **Installation evidence is configuration evidence.** The 0.2.4 host matrix records preview,
  connect, status, repeated no-op setup, disconnect and reconnect on macOS arm64, Ubuntu 24.04 and
  Ubuntu on WSL 2 for Codex, Claude Code and Cursor Agent CLI, and Cursor IDE on macOS and Linux.
  It does not assert a working model session, complete observation, or AI-powered review, and
  the Windows-side Cursor IDE Remote WSL cell remains unverified (#722, #767).
- **Real WSL 2 and AppArmor sandbox acceptance remain untested** (#720). Linux sandbox
  readiness is a fact of the client host; a Linux VM or package check does not prove WSL
  lifecycle behavior or a sandbox on a different host (#765).
- **Native Linux Claude Code and Cursor acceptance is incomplete** (#722). Their source and
  fixture coverage does not establish a native-host capability cell.
- **Native Codex multi-agent acceptance remains open** (#499, #507). Source tests and the
  0.153.4 identity repair do not prove installed host activation, correlated child observation,
  AI-powered review, corrective influence, or terminal receipt coverage.
- **Native paired overlap advice after the cold-read repair is not re-certified** (#839). The
  repair is covered by the composed service with real vault, catalog and task ledgers, including
  relock and reopen. The 2026-09-27 concurrent macOS run recorded overlap detections and
  service-to-ledger advice delivery. It did not qualify cold native restart/relock, host-visible
  consumption, or declaration-to-resolution; see the [native table](../runbooks/multi-agent-conformance.md#per-host-acceptance-table).
- **No supported capability cell is added by this release number.** Runtime support remains
  `development_unverified`; macOS arm64 and Linux x86_64 evidence covers only the exact artifact
  and jobs that ran. Linux aarch64 remains untested; native Windows is not supported.
- **Live-update evidence is bounded.** Unit tests, real-daemon switching and an installed-wheel
  replacement with old/new MCP bridges cover runtime isolation and cleanup. No installed update
  over running native host sessions or all future storage formats is claimed (#820).
- **An AI-powered review pending across the upgrade may end unreviewed.** A review job frozen
  before the upgrade and recovered after it rebuilds its packet with the larger change parts and
  can no longer match what it froze. That one review then ends as `failed` /
  `coordinator_failure` with its local-check result kept, rather than sending bytes it did not
  freeze; the next `check` composes a fresh review (#983).
- **Several-projects evidence is bounded.** Native runs in scratch configurations cover Codex
  0.162.1 and Claude Code 2.1.299 on macOS for the earlier rules, and Codex 0.144.6 and Claude
  Code 2.1.300 on Linux for the final lock and possible-user rules (the Linux Claude apply used a
  stand-in for the OS password prompt). Cursor's several-project behaviour, including a first
  setup into a folder that does not exist yet, is covered by tests only. The setup lock is
  untested when Yoetz's state folder sits on NFS, SMB/CIFS, a WSL `/mnt/c` mount or another
  network filesystem, and it does not serialise setups run by two different Yoetz installations
  at once (#1058).
- **Migration tests are not prior-release restore certification.** No golden prior-release
  upgrade/restore cell or portable recovery drill is claimed. Package installation alone does
  not prove service, data, plugin, or host-session activation.
- **PyPI 0.0.1 is a yanked name reservation.** It was yanked on 2026-09-19 because it installs
  no usable executable. Normal version selection skips it; an exact `yoetz==0.0.1` pin can
  still select it. Install the current release on Python 3.14 (#771).

These boundaries follow
[`docs/public-claims.json`](https://github.com/TheGaySupreme123/yoetz/blob/v0.3.0/docs/public-claims.json)
and
[`docs/OPEN_QUESTIONS.md`](https://github.com/TheGaySupreme123/yoetz/blob/v0.3.0/docs/OPEN_QUESTIONS.md).
Checks report issues at their recorded coverage; they do not prove the underlying work correct.

## Install

```text
uv tool install --managed-python --python 3.14.6 "yoetz==0.3.0"
```

For a one-off run: `uvx --python 3.14 "yoetz==0.3.0"`. With `uv` already installed:
`npx yoetz@0.3.0` (the dependency-free npm launcher makes a persistent `uv tool install` of the
exact PyPI distribution).

Before upgrading an existing installation, stop its hosts, hooks and service writers and follow
the [upgrade guide](https://github.com/TheGaySupreme123/yoetz/blob/v0.3.0/docs/usage/upgrading.md).

## Release integrity

Verify the artifacts against the attached `SHA256SUMS`, `NPM_SHA256SUMS`, SBOM, support matrix,
known limitations, release-evidence bundle, and `VERIFY.md`. The tagged workflow binds the
candidate artifacts to their source commit, publishes PyPI before npm, and verifies registry
downloads. This makes no signing or reproducible-build claim.
